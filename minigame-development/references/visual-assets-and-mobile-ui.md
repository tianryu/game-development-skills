# 美术、资源与移动端界面

## 从概念图到资产

- 当前项目先确认风格、轮廓、主色对比、相机、UI 比例与最小设备尺寸，再批量产图。明确参考图只用于风格分析，不能把商业游戏素材直接放进发行包。
- 设计图应接近可实现的对象数量和屏幕密度。将背景、角色、环境、图标、按钮、边框等按实际绘制层拆分，保留源图和导出规则。
- 若项目采用像素风，另行约定逻辑分辨率、像素尺寸、色阶与缩放方式。重点看轮廓干净、噪点少、相邻对象可辨认，不以“细节更多”代替品质。最近邻缩放不等于图像本身拥有正确像素网格。
- 同屏人物与地面同色时，用明度、饱和度和轮廓分离；不是简单增加高光、体积或饱和度。
- 角色状态图保持锚点、占地、帧大小和方向一致。行走、攻击、待机切换不跳位，停止移动保留有效朝向。
- UI 若用独立生成素材，交互区域和语义仍由代码管理；不要把完整文案烘焙到背景，再叠一次相同文字。
- 所有游戏标题使用图片生成技能单独制作的艺术字素材，与背景分开保存和加载，默认保留透明背景。准确核对当前游戏名称和标点；普通字体排版、程序描字或整张背景中的标题不能代替独立标题素材。
- 透明 Logo 要检查实际 alpha 通道、透明边缘和多底色显示，棋盘格画进图片不算透明。图标、Logo、封面、截图是不同物料，分别核实要求。

## 技能特效

技能特效主要使用生成的独立纹理配合程序化动画。按技能表现组合位移、缩放、旋转、扩散和淡出，并在目标手机上检查效果辨识度和密集释放时的性能。

## 素材来源与体积

字体、背景音乐和音效使用授权或许可明确、与项目风格匹配的素材。生成的素材也要核对使用与发行条件。免费下载本身不能证明可商用。

资源清单记录：作品/作者、原始页面、许可文本及版本、署名要求、修改与转换、最终使用路径。保留需随包分发的许可证；只打包运行所需文件，不把源档案、素材下载 ZIP、测试输出一起发给玩家。

字体检查实际用字与授权，进行子集化时同时覆盖动态数字、提示、错误和后续内容，保留合法字体声明。

控制同屏音效的触发密度和叠加音量。在目标手机上实听密集场景、音乐循环、响度、静音开关和切后台行为。浏览器音频通常需用户交互解锁，应有正确的首次操作体验。主菜单提供可打开的「鸣谢」，列出实际采用的素材来源、作者和需要展示的署名。

## 界面约定

沿用本规范持有者的通用偏好：减少非必要文字，突出状态和操作；UI 文案不使用 U+00B7 分隔符。若新项目明确指定不同规范，以新要求为准。

- 核心操作与次要说明有清晰层级。属性名称、效果与单位一致；增减符号必须说明作用对象，不能只显示一个负数。
- 同类信息与操作优先在同一个窗口通过 Tab 页签展示，减少多层展开、嵌套窗口和重复跳转。页签按玩家任务命名，当前项明确；切换保留筛选、滚动位置与未提交的编辑内容。确需独立详情或确认时才进入子页，并能返回实际来源，不能为了增加页签把无关功能塞在一起。
- UI 数字与实际逻辑共用数据源，预览、结果、收益明细、属性范围不得各自写一套公式。
- 按当前项目要求决定一屏展示或滚动。若关键选择必须一屏完成，应把所有选项、额外操作、说明和关闭入口一起计入高度，不能靠隐藏溢出截掉内容。
- 全场景背景按 cover 规则铺满实际可见视口，等比缩放后从构图安全区裁切。主菜单、地图、战场、场景切换和对话底景都要验收无露底、黑边或拉伸，UI 与触控独立适配安全区。横屏至少核对 16:9、19.5:9 和 20:9。
- 适配安全区、浏览器动态工具栏和短屏。横屏游戏优先用真实横屏手机的可用视口检查，例如 852 × 393 CSS 像素。竖屏游戏按实际竖屏视口检查。覆盖最小支持尺寸、常见手机、较长屏幕和项目支持的旋转场景，记录实际设备、CSS 视口与设备像素比。
- 主菜单、暂停菜单的底部图标常被固定高度截断，应检查实际布局和可点击区域，不能只靠截图看边框。

## 输入验收

- 多层窗口必须提供逐层返回，回到实际来源页并保留进度。查看账本、详情等不能形成只能继续、不能退回的单向流程；返回与关闭不得触发结算、推进日期或提交选择，推进流程应是独立明确的主操作。按实际存在的详情层级验收返回，并在短屏确认主操作始终可达。
- 同页 Tab 验收包括切换后返回原页签、保留操作上下文、活动项可辨认，以及最小支持尺寸下页签和主操作可达。若实际有多层详情，再验收逐层返回；不要为通过验收人为增加层级。

- 左侧浮动摇杆的起手热区和底座贴图分离，常用按钮和系统安全区优先。用同一坐标空间记录初次落点，后续只用该手指相对落点的拖动量计算方向；按项目规则限制移动轴，应用死区并限制最大位移。拖出热区仍由原手指控制，第二指可按其他按钮，不能抢占、重置或取消摇杆。
- 实测默认位置、两个不同落点、只点不动、拖动跨出热区、双指各自操作，以及抬指、触摸取消、失焦、弹窗和切后台后的复位。复位要同时清零逻辑输入和回到默认视觉位置，关闭遮挡层后不续用旧触点。
- UI 操作与场景点击分开判断。释放 UI 拖拽不能透传成地图点击、寻路或攻击；仅在场景中开始且符合手势条件的输入才触发场景点击。
- 弹窗或广告期间锁定背景交互，关闭后恢复应有状态，不恢复已经失效的拖拽。
- 热区按 CSS 尺寸验收，通常以约 44 CSS 像素为设计起点；实际按目标设备、布局和可达性调整，不把美术图片尺寸当热区。
- 输入自动化测试之外，至少重放一次真实触控/鼠标复现路径；引擎事件桥接与 DOM 事件可能不相同。
