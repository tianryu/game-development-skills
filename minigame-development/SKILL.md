# 小游戏开发规范

## 适用范围

用本 skill 整理或执行当前小游戏的开发和交付工作。它只记录跨项目的方法与验收要求，不决定游戏内容。实际项目的玩法、角色、地图、成长、资源、难度、奖励、广告频次、外观阶段、应用 ID 和目录路径，必须来自当前项目，不能从其他游戏继承。

项目复盘保存在 skill 集合之外的资料区，不作为本 skill 的隐含需求。新项目既可以使用某一部分，也可以覆盖已有工作约定；不要为了遵守本 skill 擅自改动已确认的方案。

## 工作顺序

每个游戏使用独立项目目录。技术栈按目标效果和目标手机的性能选择。

1. 先读项目指令和现状。将用户最新要求与旧文档、代码、测试结果核对，分别标记“要求”“实现”“验收结果”“待确认”。后续明确决定替代旧决定，但不能把未经确认的建议写成定稿。
2. 按本次任务划定修改范围和验收方式。常规可逆实现直接推进；涉及其他应用、破坏性操作或超出既有授权时，先把待操作对象和可审查结果准备清楚。
3. 有视觉分歧时，先交一张关键场景设计图确认方向。通过后再批量生成资产与实现。不要凭概念图声称实机达到某个相似度。
4. 围绕可运行的最小闭环逐步实现，每步检查实际行为；有证据表明失败再补充规则，不把一次事故扩大成所有项目的限制。
5. 交付时区分本地完成、模拟验证、真机验证、上传、审核、上线，不把其中一个阶段当成其他阶段已完成。

## 公共触控约束

所有游戏的标题都必须使用单独生成的艺术字素材，标题与背景分开制作、保存和使用，不能用普通字体排版或整张背景内的文字代替。生成、透明边缘和手机辨识度检查见 [移动端界面输入验收](references/visual-assets-and-mobile-ui.md#从概念图到资产)。

所有移动端小游戏场景的背景都必须铺满可见屏幕。背景保留原比例，按较长的一边等比放大并裁切溢出部分，界面和触控安全区单独适配。验证常见设备比例和旋转后的覆盖，详见 [移动端界面输入验收](references/visual-assets-and-mobile-ui.md#界面约定)。

同类信息与操作优先放在同一个窗口，通过清楚的 Tab 页签切换；尽量减少多层展开、嵌套窗口和来回跳转。页签切换保留操作上下文，具体布局与返回验收见 [移动端界面输入验收](references/visual-assets-and-mobile-ui.md#界面约定)。

采用左侧虚拟移动摇杆时，默认使用浮动摇杆。未操作时，底座与摇杆帽均显示在默认位置。手指落在左侧可操作区域时，两者在落点居中，输入仍为零。从该落点拖出死区才移动，手势结束或中断时立即清除输入并复位。项目明确要求固定摇杆时例外。区域、手指归属和验收见 [移动端界面输入验收](references/visual-assets-and-mobile-ui.md#输入验收)。

## 维护边界

- 本 skill 及其 references、scripts、assets 均不得放入任何具体游戏的玩法设定或运营参数。引用示例也不能让其他项目默认继承它。
- 引擎、2D/3D、像素/非像素、横竖屏、包体预算均按当前项目选择，不固化为通用要求。
- 不保存账号凭证、授权二维码、应用广告位或某项目的发布状态。
- 项目新增规则先进入项目文档；只有脱离该玩法仍有用、且经使用验证的方法，才提炼到这里。
