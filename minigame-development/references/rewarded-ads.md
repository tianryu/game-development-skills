# 激励广告集成

适用于当前项目已决定接入激励广告的任务。不自行增加广告入口、广告频次、奖励资源或难度目标。奖励方案和经济数值来自该项目设计。

## 入口与按钮

激励入口放在对应奖励有用的操作场景。按钮突出视频图标，并直接写明具体收益。

## 环境与配置

先确认平台、目标应用、广告位和方向。区分“后台已开通”“已配置广告位”“SDK 已集成”“模拟测试通过”“目标设备真实播放并获奖”。普通浏览器没有宿主 API 时，应展示准确的环境说明，不能一律报告广告未接通。

依据当前官方文档处理宿主 API 延迟注入、创建、加载、展示、关闭、异常与销毁。后台应用选中状态可能变化，任何外部写操作前重新核实目标，不继承另一游戏的配置。

## 奖励事务

- 仅由 SDK 文档定义的完整观看证明触发奖励。展示 Promise 完成、加载成功、窗口关闭本身都不是完成观看证明。
- 用户取消、未给出明确完成状态、加载失败、展示失败均不发奖，不扣除本不应扣的费用。
- 每次请求建立唯一上下文，保存广告用途、待处理选择、存档身份/版本和可领取条件。重复回调只执行一次；广告返回时如果原操作已失效，不把奖励套用到其他存档或新局。
- 领取行为原子化更新存档与界面。统计、预览和奖励明细共用实际发奖计算，不把既有余额或已经发放部分重复计入。
- 正式环境不得在失败时静默切换为“模拟成功”。开发模拟应显式隔离，不污染真实存档或发行包。

## 生命周期

展示期间阻止重复请求及背景操作；按项目语义暂停音频、计时和输入。通过统一清理路径恢复状态。

设置合理超时和有限重试；超时后清除忙状态、移除监听并失效旧请求，迟到回调不能再发奖。不能仅给 Promise 加超时却保留仍能生效的 SDK 回调。

退出弹窗、切后台、重新开局、存档切换等要与广告生命周期一致。不要通过全局监听意外关闭领取弹窗，或让结束回调恢复已经退出的场景。

## 验收矩阵

先用隔离的 Mock 验证完整观看、提前退出、广告不可用和重复回调。完整观看只发奖一次，其余情形按奖励事务规则处理。根据接入路径补查缺少完成标记、加载或展示错误、连续点击、超时及迟到回调、切后台和状态切换。最后在平台目标设备验证真实广告，正式环境只接受 SDK 明确确认的完整观看结果。

交付报告明确哪一层已验证、哪些因授权或环境尚未验证，保留错误类型与版本，避免记录敏感凭证。
