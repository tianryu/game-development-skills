# tianruy游戏开发规范

以可复用的工程流程完成用户本次任务。适用于不同游戏、引擎和平台；项目名、路径、主干名、版本分支、工具与目标语言从当前工程读取，不能照搬来源项目。

## 1. 任务与规则边界

- 先区分分析、记录待办、出方案、实现、提交、同步、推送和发行。用户说“先记录”“不要修改代码”时只记录；授权实现不自动包含推送或发行。
- 同一事项以用户最新明确要求为准，再结合当前项目规范与最新已确认设计。历史方案、旧测试及旧交接不能覆盖现行要求。
- 已经明确授权的步骤继续完成，不重复确认。仅在缺少会改变实施结果的关键信息或授权边界不清时澄清，同时推进不依赖答案的工作。
- 不把单个功能的例外推广成全项目规则，不把某一游戏的玩法、美术或固定技术栈推广到其他游戏。
- 先读项目当前交接与本批相关入口，定向搜索定义、调用方和验证方式。避免默认通读历史、重复读取已掌握的文件或无关扩大任务。

## 2. Git 与多人协作

- 开始任务、写入及提交前核对真实目录、当前分支和工作区状态；静态记录不能代替 Git。非 Git 工程按其实际版本管理方式处理。
- 同一目录的不同聊天共享工作区与当前分支。保留其他任务的未提交、暂存和未跟踪文件；不能擅自清空、覆盖或混入本批提交。
- 项目存在完整版与 Demo/渠道分支时，共用修改先在已确定的主干完成，再按授权同步。保留版本专属内容，不把裁剪配置反向覆盖完整版。
- 位于版本专属分支且任务归属不明时，明确实际分支与目录，确认修改范围。已有本批明确授权不重复询问；切换前检查脏工作区和 worktree，必要时使用独立工作树。
- 每次推送前先获取并整合目标分支对应远端的最新提交。拉取失败不能跳过后直接推送；多个分支分别同步并核实结果。
- 分别报告修改、提交、同步、推送、导出与发布状态，不把其中任一步代替其他步骤。

## 3. 代码、数据与交互

- 新增或修改代码用中文注释解释职责、关键意图、边界及易错原因；不要逐行复述语法。公共函数优先有用途说明；JSON 等不支持注释的格式在读取代码或配套文档说明。
- 页面控制器负责流程及跨组件协调，组件负责自身显示、输入和局部刷新。优先复用已有组件、公共操作与正常入口，避免功能只在测试页可用。
- 同类信息和操作优先在同一个窗口通过 Tab 页签展示，尽量减少多层展开、嵌套窗口与重复跳转。页签按玩家任务组织并清楚标出当前项；切换保留筛选、滚动位置和未提交的编辑内容。只有独立详情或确认确有必要时才进入子页，并能返回实际来源；不能把无关功能硬塞进同一组页签。
- 运行规则使用结构化数据、稳定 ID 与明确接口；显示名称、翻译和自然语言描述不作为规则解析依据。改名按 ID 核对关联引用，不能盲目全文替换。
- 显示、预览和动画不能产生第二次业务结算。会改变持久数据的操作明确校验、提交、失败回滚和重复请求处理边界。
- 玩家文案直接说明行动和必要条件。删除重复标题、无效果占位句和内部实现术语；保留会影响决策的对象、代价、限制及例外。
- 不使用中点字符（Unicode U+00B7）作标题、文字、界面、列表或状态信息的分隔符，也不用类似装饰圆点替代。按语义使用空格、换行、逗号、冒号或自然语句。历史引用、专名原文及代码运算符按必要性保留。
- 同一信息在正文、提示、日志、预览和操作页保持一致，复用权威数据或显示入口。已有图标能明确表达时避免重复标签，但不能省略会产生歧义的单位或条件。
- 图标优先：能用清楚、可识别的图标表达的信息，尽量不用重复文字。资源与费用采用“数字 + 对应资源图标”的排版，例如数字180后接金币图标，不写“180金币”，也不显示字面加号。费用靠近其对应操作，图标与数字统一视觉大小、基线和间距；不能因此省略影响决策的条件或用含义模糊的图标强行替换必要文字。

涉及分支冲突、组件结构、事务、输入、设置或性能时，按需阅读 [工程与交互细则](references/engineering.md)。Godot 专项只在使用 Godot 时适用。

- 全局动效默认：游戏里所有内容的出现和消失都要渐入渐出，包括提示、金币虚影、建筑虚影、按钮、窗口、角色/物件、状态替换和特效。只有用户明确要求某处不做时才例外；呼吸、位移或缩放不能替代显隐渐变。实现及验收见[显隐动画规范](references/visibility-transitions.md)。
- 采用触屏摇杆时使用有默认位置的浮动摇杆，左右各自占可用视口外侧三分之一的起手区。移动端右侧按钮留足边距，右上角预留给宿主控件。按 [工程与交互细则](references/engineering.md) 验收触点与安全区。

## 4. 期待感、即时反馈与成长感

- 核心玩法按期待感、即时反馈、成长感三方面分别验收。策划、分配内容和迭代时，为每项预先约定一个或多个可观察的玩家行为或结果，并通过实际游玩取证。
- 期待感：让玩家知道近期目标、投入、可获得的收益和下一次变化。展示接近完成的进度和可理解的预告；不把不确定结果伪装成保证收益。
- 即时反馈：输入被接受或条件不足时立即给出可见或可听的响应。过程推进、结果到账和后续影响应清楚对应。区分操作响应和最终结果，反馈与权威数据同步，动画不重复结算。
- 成长感：成长应改变玩家的能力、策略、选择空间或可见成果，而不只是放大数字。新内容增加有意义的变化；核心操作保持容易理解，新规则按需要引导。
- 设计回访动机时，优先让玩家期待新变化、尝试新方案并看见旧投入的成果。签到等回访奖励应有节奏、奖励差异和清楚预告，不能代替主体内容。
- 内容时长不能靠重复劳动、同质任务、强制等待或故意减慢节奏凑够。时长目标、内容数量、奖励金额和回访周期按具体项目确定，不作为通用固定配置。
- 验收用真实游玩观察：玩家是否理解下一目标，能否解释操作后的变化，成长是否带来新的有效决策，回来后是否有值得继续的内容。记录样本与问题；设计了这些机制不等于已经证明留存或时长达标。

## 5. 验证范围与证据

- 制定详细开发步骤时，同步为各里程碑写可执行的验收标准，覆盖美术、玩法和操控。按项目能力确定明确的通过条件、实际入口、设备与证据，按 [定向验证与报告](references/verification.md) 核对。
- 日常只验证本次改动及必要关联路径；纯文档只核对内容、链接和交付文件，不运行游戏测试。
- 完整套件、全工程回归、完整旅程及大规模采样只按用户本批明确要求执行。历史授权、旧清单和“保险起见”都不能自动扩大范围。
- 在当前工程运行选定检查，测试存档、配置和输出独立隔离；不默认复制整个工程和导入缓存，不触碰正式玩家档。
- 测试通过须对应本次源码及实际执行结果。发现编译、导入、夹具或接口问题先分诊，不把无效测试结果当作产品结论。
- 无头检查不能代替实际图形界面和操作；截图不能证明按钮可点；合成输入不能代替实体设备；本机通过不能代替跨平台验收。
- 保留原始失败、修复和复测记录，写明未测范围。没有证据时写“未测”或“证据不足”，不写“全部正常”。

编写用例、复现问题或输出测试结论时阅读 [定向验证与报告](references/verification.md)。

## 6. 本地化、资源与发行

- 新制静态视觉素材必须用图片生成技能制作。动画使用独立生成的纹理并由程序驱动，禁用逐帧贴图动画。美术采用朴素、平面、有手绘感的表现，以 Steam 独立游戏成品完成度为目标，按已确认的设计图 1:1 验收。美术、声音、字体和特效制作见 [美术与素材制作细则](references/art-production.md)。
- 所有游戏的标题都必须使用单独生成的艺术字素材。标题与背景分开制作、保存和使用，不能用普通字体排版、程序描字或烘焙在整张背景里的文字代替独立标题素材；具体制作与验收见 [美术与素材制作细则](references/art-production.md)。
- 使用开源素材的游戏须有玩家可打开的鸣谢菜单。署名和随包许可按 [本地化与交付细则](references/localization-release.md) 核对。
- 已启用多语言的项目，新增、修改、删除玩家文案时同批维护相应语言与生成资源；不因使用本 Skill 给单语项目擅自增加多语言。
- 翻译只作用于显示层；切换语言只重排和刷新，不改变业务状态、随机结果或进度。长期设置与单次游戏进度分开保存。
- 工具、校对表、设计文档、测试和临时输出进入明确的开发目录，隔离引擎导入及发行；正式运行依赖不能引用这些隔离产物。
- 文件清理检查正式引用、动态加载、公共回退及仍用预览；先保留必要证据与可恢复副本，再在授权范围内移除。不能只凭文件名、一次搜索或截图未出现判断无用。
- 发布前检查实际包内容和独立运行，正式依赖、许可证及生成资源应完整，测试入口与调试能力应被排除或真正禁用。

处理显示文案、多语言、文件清理或构建发布时阅读 [本地化与交付细则](references/localization-release.md)。项目的具体画风、音色和压缩预算以已确认设计与目标设备为准。

## 7. 收尾与交接

- 沿当前仓库既有格式更新简短交接、执行计划及必要的权威设计；接口变化才更新接口契约。详细过程只在一个报告或开发历史入口保存，其他位置引用，避免复制多份日志。
- 交接保留本批实际完成、验证范围、未决项与下一步。区分“已记录”“已实现”“已验证”和“待用户体验”，旧批次完成结论不自动继承到新代码。
- 交付先说明改变了什么及实际效果，再给验证与限制、文件入口和 Git 状态。项目要求进度统计时按其真实验收口径报告，不沿用其他游戏的关卡数量。
- 性能或相似度百分比须说明比较对象、基线与计算方法；人工主观对照必须明确标注，不能包装成精确测量。
- 测试结束后核验归档，再清理本批可再生成的临时副本与缓存。确认绝对路径及活跃进程，不删除其他会话仍使用的内容。
