# 工程与交互细则

仅阅读本次涉及的部分，不把下面各项自动扩展为每次任务的检查清单。

## 分支与多电脑协作

- Git 工程先用 `git branch --show-current` 与 `git status --short --branch` 取得事实。切换或并行开发前检查 `git worktree list`；确认 upstream，不从分支名字猜远端。
- 同步范围按功能和实际差异确定，不能只挑少数文件便声称“当前代码已全部同步”。若用户要求全部备份或全部同步，核对未提交、未跟踪、本地未推送提交及忽略文件边界；说明实际包含和排除项。
- 多电脑会变化的工作分支标记、引擎路径、工具路径及本地临时设置用机器本地配置记录；需要共享的配置保留模板，不能让提交的“当前分支”字符串覆盖真实 Git 状态。
- 冲突处理按两边最新意图整合，检查是否遗漏功能、翻译、生成数据和版本专属设置；消除冲突标记不等于完成整合。验证受冲突影响的实际路径，不擅自跑全工程回归。
- 首次发布新分支也先获取远端状态，确认不存在相冲突的远端分支，再设置跟踪。推送成功后核对远端提交，不凭本地分支存在判断成功。
- 已有脏文件中的定向修改保留其他修改；提交只纳入获授权的范围。用户要求完整备份时按明确边界执行，不把“未经本批验证”误写成“备份中不存在”。

## 组件与规则实现

- 先定位真正生效的数据源、公共执行入口和正式调用方，不能只改旧场景、未启用定义、演示页面或说明文档。
- 同类能力通过结构化配置和公共操作实现；内容 ID 用于识别，不在页面控制器中不断堆叠按名字判断的特殊分支。
- 不用名称后缀或显示文案解析等级、类别、状态等程序数据。同名对象可能具有不同身份，修改引用时按稳定 ID 与实例 ID 区分。
- 预览、运行数值和存档重建尽量复用同一规则来源，避免多份手写公式漂移。测试仍须有独立预期或可观察结果，不能仅用同一函数互相比对证明正确。
- 临时值、永久值、派生值及实例状态明确来源和生命周期，避免重复叠加；恢复快照不应重走会重复产生副作用的初始化入口。
- 正式系统、编辑工具、测试夹具与显示层各自有职责。修旧测试以适配最新确认规则，不能为旧测试通过恢复已取消逻辑。
- 历史兼容由项目阶段与用户要求决定。开发期已明确不兼容时删除失用逻辑，不另加迁移补偿；已发行项目不能套用此约定擅自破坏存档。

## 事务、随机与存取

- 购买、领取、升级、进度推进等状态变更由业务层再次校验资格和资源，不能只依赖按钮是否禁用。
- 明确一次操作的原子提交边界；关联记录不能只保存一半。保存失败后保留可恢复状态，避免先宣告成功再丢失进度。
- 防止连点、重复回调、动画完成、退出重进和恢复存档导致重复扣费、重复奖励或重复推进。续接界面的重试不能重新执行已成功的事务。
- UI 预览、悬浮、排序、筛选、重排与语言切换保持只读，不在这些路径生成新业务结果。预加载也不能提前消费随机或暴露未揭示内容。
- 随机源与重放边界按当前游戏设计明确，不把来源游戏的种子策略强加给其他项目。展示层不额外消耗随机流；需要保存的既定结果实际持久化，不靠重新抽取伪装恢复。
- 存档或跨进程数据核对整数、浮点及随机状态的精度；不能让序列化改变实例身份、次数或已确认结果。
- 返回菜单、退出、取消和恢复分别遵循已定义的提交边界；不能把关闭弹窗当成默认确认。设置偏好与游戏进度隔离。

## 界面与输入工程

- 以实际用户路径验收交互：打开、选择、确认、取消、返回和重进。禁用状态、命中范围及后台校验一致，不能只做视觉禁用。
- 状态变化后及时刷新相关余额、费用和可操作状态；所有页面从同一事实来源读取，避免旧报价或旧数据残留。
- 悬浮与展开尽量保留稳定命中区域，快速移入移出从当前状态接续；关闭、滚动、列表重建或对象释放时清理悬浮和失效引用。
- 提示或按钮显隐不应挤动正在命中的对象；留足可操作空间，避免提示遮挡唯一操作。满载、长文本和屏幕边缘按支持范围核查。
- 弹窗优先消费自己的返回/取消输入，防止同一次按键穿透底层。场景切换的空帧、对象离树和窗口失焦都要有可恢复行为。
- 页面刷新、切换语言或展示动画不能改变实际业务顺序。只锁定必要的重复提交或冲突操作，不把局部忙碌扩大成无关内容全部不可查看。
- 使用鼠标、键盘、手柄或触控时复用同一业务行为；设备提示应反映当前实际输入，不能为第二种设备复制一套会漂移的规则。
- 普通设置采用即时应用并自动保存，返回只关闭设置，不负责提交或回滚。需要风险确认或回退的设置若项目已有明确约定，保留其机制，不机械推广即时生效。

### 移动端触控

- 采用摇杆时，闲置底座和摇杆帽显示在各自默认位置。左摇杆以可用视口最左三分之一为起手区，右摇杆以最右三分之一为起手区。仅为当前玩法所需的摇杆划区。手指在区域内落下时，底座和摇杆帽以落点为中心，输入为零。拖出死区后才发力。
- 每个触点由最初命中的控件持有，越区拖动时仍归原控件。按钮优先于其下方的摇杆起手区。松手、触摸取消、失焦或退后台时立即清零对应输入，摇杆回到默认位置。重新进入时以新触点开始。
- 右侧操作按钮按拇指实际活动范围布局，按钮外形和有效热区都与屏幕边缘留出舒适间距。检查横竖屏目标比例、设备安全区和系统手势区。游戏右上角留空。TapTap 等小游戏宿主的退出键及其交互区域优先，排除游戏按钮、摇杆起手区及场景输入，并在实际客户端验证。

## 性能定位

- 移动端小游戏在排开发计划时先按目标设备确定帧耗时、峰值内存、首屏加载及资源体积预算。正式渲染重点控制纹理尺寸、同屏粒子、透明叠绘、绘制批次和常驻资源。适配低端机时先收缩装饰性效果，保住玩法线索、操作反馈与已确认的视觉基线。目标机与发行宿主内检查冷启动、常用操作和高负载场景。
- 先复现卡顿并拆分加载、解析、存取、界面重建和渲染耗时，再选择优化点。区分冷启动、首次打开、暖缓存及连续操作。
- 对点击路径中的同步重读、重复解析和全量重建做定向改进；按需异步预读和复用缓存，并定义就绪状态、容量、失效与释放条件。
- 缓存和预加载不得改变业务随机、候选结果、保存时机或交易语义；不能靠推迟关键落盘、跳过校验制造更快假象。
- 有待完成的异步资源不能立即同步取回造成主线程再次阻塞。页面被关闭或重建后处理过期回调，避免旧结果覆盖新页面。
- 在相同设备、平台、渲染后端和操作条件下比较；至少交代冷暖差异、样本数及最长停顿。无头耗时不能代表图形界面帧率。
- 演出总时长与卡顿帧分别统计；没有稳定改善就如实报告，不能把某一次最快值当作全部体验。

## Godot 条件专项

仅用于 Godot 工程。版本、语言和命令从当前工程与本机发现，不固定为某个版本或某台电脑的绝对路径。

- 可视化布局优先维护可编辑的 `.tscn` 组件；脚本填充运行时数据，动态数量对象实例化预制体，避免页面脚本拼装大量固定 Control。
- 项目若选用 GDScript 或 JSON，沿用当前规范；不为了应用本 Skill 强制其他引擎换语言或数据格式。
- 对本次脚本执行适用的解析或定向无头检查；涉及渲染、输入或排版再用实际图形后端验证。不能仅凭 `--headless --quit` 成功认定交互通过。
- 临时和工具目录使用 `.gdignore` 隔离导入，并配合导出排除；`.gitignore`、`.gdignore` 与发行过滤用途不同，不能相互替代。
- 不为测试复制完整 `.godot` 缓存。测试使用独立用户数据路径，验证节点生命周期、异步等待和自动加载依赖时避免触碰玩家档。
