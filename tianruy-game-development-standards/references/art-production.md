# 美术与素材制作细则

## 素材来源

- 新制静态视觉素材一律用图片生成技能生成，包括背景、角色和道具、UI 图标、装饰以及特效纹理。按设计拆成可独立定位、旋转、遮挡和替换的层，保留原图及可追溯的生成参考。
- 所有游戏的标题都必须使用单独生成的艺术字素材。用图片生成技能单独制作标题，准确保留已确认的游戏名称、文字与标点；与背景分开保存和加载，默认交付透明背景。不能用普通字体排版、程序描字或整张背景内的标题替代。核对实际 alpha、透明边缘、深浅背景和手机缩小后的辨识度；标题改名时重新制作对应素材，不能只改一处显示文案。
- 游戏画面、预览和交付构建使用对应的素材。严禁用程序绘制的几何图、生成图像或程序合成的声音代替素材。编辑器里的碰撞线、命中区等调试可视化隔离在开发入口。布局、文字排版、裁切、合图和对已有纹理的运行时处理按各自职责实现。
- 音乐和音效使用实录、专用音频生成能力制作的成品，或已获发行许可的音频。取得成品音频后允许剪辑、混音和响度处理。
- 字体从网络寻找与项目气质相符的字体，核对作者或官方发行页、实际许可、目标语言字形、嵌入与再分发条件。游戏内小字号、长文本和必要的回退字形在目标设备核对。项目明确采用第三方视觉素材时核对来源及许可。第三方素材的登记和鸣谢见 [本地化与交付细则](localization-release.md)。

## 设计图和手绘风格

- 以 Steam 独立游戏的成品完成度要求美术。先为当前项目的关键场景和界面出可实现的设计图，确认构图、比例、透视、色板、笔触、轮廓、明暗和界面层级后再批量制作。正式画面以确认稿为基准 1:1 还原，验收口径见 [定向验证与报告](verification.md)。
- 画面呈现朴素、平面、有手绘感的风格。用清楚的轮廓、简洁的色块、自然的笔触和克制的明暗塑造对象，避免油亮高光、过度渐变和渲染式立体光影。按确认稿核对角色、场景、界面及特效的整体一致性。
- 对频繁出现的场景和对象准备有用途的变体，例如同一套树形中的疏密、枝形和季节差异。维持共同的视角、色板、轮廓与笔触，检查连续游玩和同屏摆放的重复感。不同变体保持原有的辨识和可操作边界，具体设计基线按已确认稿实现。

## 动画与特效

- 禁止使用逐帧图、精灵序列或序列帧图集播放动画。用图片生成技能制作独立纹理，再用代码或引擎驱动位移、旋转、缩放、透明度、骨骼或网格变形。静态纹理可以合入图集以优化加载和绘制。
- 可动部件保留正确的层级和锚点。例如船桨只用一张独立桨图，固定桨轴，按输入旋转和移动，桨叶入水的路径与玩法状态一致。动画的时机、反馈和结束条件由运行逻辑驱动。
- 特效可以参考 [pixelfx](https://github.com/patch-gg/pixelfx) 的节奏、发射、轨迹、遮挡和衰减写法。按当前画风和引擎移植原理，使用单独生成的水花、光斑等纹理，以程序控制粒子、变形或着色器动画。没有合适的参考时仍用生成纹理配合程序实现。直接复用第三方内容前核对许可和署名。
- 显隐使用 [显隐动画规范](visibility-transitions.md)。移动端使用项目性能预算限制粒子数量、透明层叠加和纹理体积，按 [工程与交互细则](engineering.md) 检查真实设备上的最繁忙场景。
