# 定向验证与报告

## 选择本批检查

按改动选择最小充分证据，不将下面类别自动组合成全套。

| 改动 | 对应验证 |
| --- | --- |
| 文档、任务清单、Skill | 内容、相对链接、格式及交付文件可读性 |
| 单项数据 | 格式解析、目标字段及直接派生关系；不为一行可逆改动另造镜像测试 |
| 业务逻辑 | 正常行为、相关边界、失败与重复执行；有持久化影响才验证存取 |
| 玩家文案 | 当前实际显示、动态句、已启用语言和相关排版 |
| 美术与动效 | 同条件实机截图与确认设计图 1:1 对照，录屏核对动效及风格 |
| 玩法 | 正式入口的正常操作、反馈、进展及失败恢复，按设计观察玩家预期与成长 |
| UI 与输入 | 正式入口、真实操作、显隐、禁用、取消/返回及受影响设备 |
| 性能 | 同条件前后计时、冷暖差异、耗时来源及正确性约束。移动小游戏在目标真机和发行宿主中对项目预算检查 |
| 构建发行 | 实际包清单、正式依赖、调试隔离及独立目录运行 |

完成选定检查后交付。仅当新修改、失败或未解疑点出现时扩大直接相关验证；完整测试须用户本批明确要求。只改文档不要启动游戏。

## 开发步骤与验收标准

写详细开发计划时，为各里程碑同时写验收项。每项列出正式入口、操作步骤、预期可观察结果、覆盖设备或状态和证据。阈值按项目可实现的目标设定，以明确的通过条件判断。

- 美术按已确认的设计图 1:1 验收。使用同一画幅、分辨率、镜头、场景或 UI 状态、语言和安全区对齐实机截图。用并排或叠图核对构图、尺寸、位置、素材、色板、笔触和层级，逐项标出偏差。其他屏幕比例按已确认的响应式布局验收。动效与显隐用录屏核对。相似度的主观百分比不能代替对照证据。
- 玩法按期待感、即时反馈、成长感分别验收。写明玩家在行动前能预期什么、操作后怎样立刻确认输入，以及练习或推进后怎样体现成长。通过正式入口检查对应的正常路径、常见失手及恢复。
- 操控在目标设备验证实际命中、反馈、屏幕边缘、触点归属、取消、切后台和返回。启用摇杆时再测默认位、有效起手区、死区与复位。移动小游戏还要用实际宿主核对安全区和系统控件。

## 执行与数据隔离

- 直接在当前工程运行相关脚本、场景或静态工具，记录实际命令。测试存档、配置及输出使用单独目录；先验证隔离确实生效，再做故障注入。
- 不默认复制整个项目、素材和导入缓存，不为了生成报告或版本指纹重新启用项目已停用的旧工具。
- 记录实际分支、提交及影响本批的未提交修改，按需要保存相关文件哈希、引擎、平台、图形后端、语言、分辨率与输入设备。
- 并发修改时核对受测文件是否变化。发生变化只重测受影响路径或注明结果对应的版本，不能把不同版本的结果拼成同一版已通过。
- 先处理编译、导入、测试接口和夹具失效，再执行有效用例。旧通过只供定位，不自动继承。
- 故障注入限定本批测试目录或测试接口，不能把玩家存档路径设只读、改坏配置或清空正式数据来试验。

## 结果可信度

- 功能夹具可以模拟前置，但报告要标明。测试入口直达、免费资源、模拟胜利或跳过流程不能计为正常游戏体验已完成。
- 无头检查证明其覆盖的结构和逻辑；真实图形界面操作才证明实机路径。图片正确不代表点击正确，合成按键不代表实体手柄验收。
- UI 核对本批相关的长文、满载状态、窗口边缘与支持分辨率；不要自行扩展为全平台、多设备完整矩阵。
- UI 故障至少给出操作步骤、预期、实际、发生条件和证据。难以复现时明确是观察或推测，不能写成已定位根因。
- 运行超时、程序阻断、测试器失效与玩家失败分别记录。无进展要判断是否合法等待或预算截断，不直接等同死锁。
- 自动策略与真人表现分开。只有用户要求体验或难度测量时才安排相应样本；先验证测试策略按真实可见信息操作，再解释数据，不据失败样本擅改玩法或数值。
- 不挑选有利样本、不丢弃失败；百分比写明分母、样本条件和统计方法。人工评分标明主观维度与依据，不称像素级或严格统计结论。

## 诊断与复测

- 优先解决数据损坏、无法启动、流程阻断和必要操作不可用，再处理规则与描述不一致及一般可用性问题。测试工具故障单列，建议与确定缺陷分开。
- 先在对应版本复现，再决定修代码、修文本或更新旧夹具。不能为了通过旧断言回退用户新设计。
- 修复后复测原触发条件及直接相邻路径。新增回归须能检测独立行为或真实故障，不写只复述实现的断言凑数量。
- 原始失败和最终复测都保留；新功能尚未执行、设备缺失、发行未测都明确列出，不能用“基本没问题”盖过缺口。

## 最小报告

规模随任务调整。小修改一段说明即可，复杂问题使用项目已有报告格式，至少能回答：

1. 改了什么，实际受测版本是什么。
2. 执行了什么命令或真实操作，结果如何。
3. 是否有失败、修复、残余问题和未测范围。
4. 证据在哪里，下一步需要什么。
5. 是否提交、同步、推送、导出或发布。

只把确实执行的检查写入通过项，不能为填满报告追加未经要求的全套测试。

## 归档与清理

- 只保留足以复现和审查的报告、相关源码指纹、原始结果、日志、截图及必要快照；不把整份工程和导入缓存永久当作证据。
- 清理前核验归档文件可读，确认待清理绝对路径在本批临时范围内，检查进程或其他会话占用。未完成取证的问题保留最小材料并注明用途。
- 可再生成副本与正式工程、玩家档、独占源文件及已归档证据分开处理。没有确认清理范围时不批量删除。
