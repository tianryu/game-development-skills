# H5 运行与交付

## 运行方式

ES 模块、样式和资源请求应通过 HTTP(S) 预览验证。双击 HTML 产生 file:// 页面时的模块限制、来源限制或路径失败，不应立即诊断为游戏布局损坏。

本地预览服务是开发工具；发行平台如何托管页面应依据平台文档确认。不能让正式包依赖开发者的 localhost、文件绝对路径或本机服务。

检查构建配置和运行时代码两层资源路径。打包工具的相对 base 不会自动修复所有硬编码的 /assets 路径。至少验证站点根路径和嵌套子目录访问，以及字体、音频、动态图集与延迟加载资源。

## 存档与配置

- 正常测试不清空用户现有存档。测试身份/存储应隔离，发行环境不得开放开发用资源修改入口。
- 更改存档结构或新增字段时定义默认值与迁移，先备份无法解析的数据，再提供恢复途径。
- 状态展示和规则计算共用模型；限制与上限明确来自产品要求，不能因为视觉资源有限就无意限制逻辑成长。
- 不假定开发构建、预览构建、已打包 ZIP 和远端版本是同一个产物；用版本、哈希和实际资源确认。

## 包体检查

按当前平台的实际上传模式确定结构、压缩方式和预算。分别记录 ZIP 字节数、解压字节数、文件数与首屏资源量。

如果平台明确要求“ZIP 根目录只有一个文件夹，该文件夹内有 index.html”，可用本 skill 的只读工具：

```text
python scripts/inspect_h5_zip.py <发行包.zip> --dist <构建目录>
```

按当前项目和平台需要追加 `--max-unpacked-bytes`、`--max-zip-bytes`，单位是字节，工具不内置任何平台或项目容量上限。

工具检查 ZIP 完整性、目录层级、安全路径、重复条目、入口、大小及可选的文件哈希对比。不上传、不解压、不修改构建目录；它不能证明游戏能够启动，也不代替平台解析或真机测试。

## 发布和素材验收

发布前明确当前授权是准备文件、创建应用、上传草稿、提交审核还是正式上线。接口名称不等于实际副作用；若“保存”或“上传”连带提交审核，不能用它完成仅准备草稿的任务。

真实截图与录屏应来自对应构建，使用用户指定或目标设备的实际比例。不能把概念图当实机，不能默认所有手机都是 9:16。避免拉伸补齐比例；测试状态、无障碍工具或开发面板不要误带入物料。

实机录屏按 [录屏制作流程](release-materials.md#实机录屏制作) 取材、剪辑和配乐。

记录文件尺寸、时长、编码、音轨与当前平台规格。转码不能掩盖游戏原本的画面和运行情况；宣传剪辑与连续实机录屏分开标注。

交付清单包含：版本、包体绝对路径、SHA-256、大小、结构与运行验证、第三方许可、尚未完成的平台验证。用户要求本地交付时，不额外上传或触发审核。
